# Glass UI, interaction and accessibility review

Reviewed 14 October 2026 against the approved composition reference, current product decisions and the real hosted application. The review includes fixes, source inspection, deterministic regressions and browser journeys. It is not a WCAG certification or a substitute for assistive-technology and physical-device testing.

## Citation behavior

Workers use the framework's cited output capture. Final typed answers use `defineOutput`; acceptance still calls public `weaveSourcesIntoResult`. The old per-cell call appended a full Sources list to every cell. The fix retains its inline weaving and separates only a complete matching trailer. A custom or incomplete bibliography is left alone.

Source grouping uses the full destination, so two distinct bookmarks or PDF pages stay distinct. Progress grouping may combine fragments of the same returned web page; that does not change answer citations. No claim-to-source link, bookmark or page-inspection receipt is invented. Grouping a citation is a presentation change, not an assessment of its factual support.

The real Wikipedia parallel journey completed both workers and produced a final table with two distinct source destinations and one grouped inventory. It also exposed the repeated Markdown table and the missing Wikipedia progress metadata. Its historical result is a counterexample, not a claim of flawless model compliance. Exact-table normalization has a deterministic regression; it does not force all superficially similar tables to collapse.

## Remaining acceptance work

- Public Lightbox must supply accessible close, focus entry/containment/restoration and background isolation. This is the principal open accessibility blocker.
- Public fold must expose metadata for the stock Wikipedia ability before its progress strip can show sources.
- Run VoiceOver/NVDA and physical touch/soft-keyboard/safe-area journeys; test denied microphone permission and spoken history search. Viewport resizing does not simulate those devices.
- Recheck actual desktop package behavior after the UI update. The prior package receipt is historical.
- Measure response/motion targets and complete human answer-quality review. Existing verification gates remain in force.

No addon access, framework UI fork, alternative model scheduler or private citation parser was introduced. See [verification](verification.md) for the broader Phase 1 evidence boundary.
